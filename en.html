Privacy Policy

Last updated: May 17, 2026 · Effective date: May 17, 2026

Summary: ZikirMatik Pro does not sell your personal data, does not collect your email/phone/real name, and does not require account creation. In standalone use, all your data stays on your device. When you use the Group Dhikr feature, only group-related data (nickname, group name, task counters) is processed securely on Firebase Firestore. Ad and crash telemetry is anonymous.

2. Data We Collect and Where It Is Stored

2.1 Data Stored Only On Your Device

This data is not sent to any server and is kept only on your device in the Room database and DataStore:

  • Your dhikr list, custom dhikr entries, and targets
  • Counting history and session records (date, count, which dhikr)
  • App settings: theme, language, font, sound/vibration preferences, daily hadith notification time
  • Onboarding and privacy policy acceptance status
  • Premium purchase local verification state (Play Billing token)

2.2 Anonymous Analytics & Telemetry (Firebase)

  • Firebase Analytics: Screens viewed, buttons tapped, usage events such as dhikr completed / qibla opened / onboarding finished. No content or personal data.
  • Firebase Crashlytics: Crash stack traces, device model, Android version, anonymous Firebase Installation ID.
  • Firebase App Check: Verifies that server calls originate from the legitimate device and app.

2.3 Anonymous Global Statistics

To show which dhikr are most popular globally, anonymous aggregate counter updates are sent to the _globalStats collection in Firebase Firestore. This data does not carry user identity, IP, or device identifier; it is only aggregate counters like "X dhikr received +N count today".

2.4 Group Dhikr / Khatm Feature (Cloud Data)

This feature is optional. It is only activated when you create a group or join one. The following data is processed on Firebase infrastructure:

  • Firebase Authentication (Anonymous): A random UID automatically assigned to your device. It does not include email/phone/real name. It remains valid until you uninstall the app or request UID deletion.
  • Firestore (us-west1 region):
    • Group title, intention note (e.g., "In memory of my grandmother"), privacy setting (open/private)
    • Invite code (6 characters) and creation date
    • Task definitions (type: Tahlil/Salawat/Istighfar, target count, assignment status)
    • Member list: only the nickname you provided + anonymous UID + role (admin / participant) + join date
    • Task progress counters (how many, when counted, used for speed analysis)
    • Audit log: admin actions (who approved which task / who removed whom)
    • Premium capacity boost attempts (ad-watch / Premium purchase records)
  • Cloud Functions (server-side): The following critical operations are run as server-side transactions: createHatimGroup, joinHatimGroupWithCode, assignTask, completeTask, approveTask, rotateJoinCode, addExtraReading, removeParticipant, updateGroupCapacity, boostGroupCapacityWithAd, leaveGroup, deleteGroup. They are used to prevent fraud, enforce capacity/membership rules, and block count manipulation.
  • App Check (Play Integrity / SafetyNet): Verifies that server calls come from a real device and the genuine app; prevents automated bot/spam access.

2.5 Ads (Google AdMob)

If you are not a Premium subscriber, banner ads and rewarded ads (for capacity boosting) are shown.

  • Google AdMob may process the Android Advertising ID (AD_ID) and session info to serve personalized or non-personalized ads.
  • For EEA / UK / Swiss users, a UMP (User Messaging Platform) consent dialog is shown.
  • Personalized ads are not shown without your consent.

2.6 Purchases (Google Play Billing)

Premium subscription is processed through Google Play Billing. ZikirMatik does not see or store your card number or payment information. The purchase outcome (premium active/not) is verified with a token received from Google Play. The premium status per device is stored in the users/{uid}/isPremium field in Firestore.

3. Location Data (Qibla Only)

Coarse and fine location are used when you open the Qibla compass. The location is only used on your device for calculation; it is never sent to any server and is not stored.

4. Camera Data (QR Scan Only)

The camera opens when you want to scan a QR invite code. The image from the camera is processed in real time on the device, not saved, and not sent outside. Only the text of the QR code is read.

6. What We Do — Brief Description

  • Counting: Tap counts are written to the local database; every 10 taps, an anonymous global statistics counter is updated.
  • Creating a Khatm Group: A transaction runs through a Cloud Function; the group and invite code are written to Firestore; your anonymous UID is marked as the group admin.
  • Joining a group: The invite code is verified via Cloud Function; your nickname and anonymous UID are added as a member; group capacity is checked.
  • Completing a task: The counting result is sent to a Cloud Function; if the counting speed looks suspicious, the task is put under "review" and waits for admin approval.
  • Removing a member / deleting a group: Admin actions are logged in the audit log; the leaving member's assigned task is released.
  • Premium purchase: The Google Play Billing token is verified, the users/{uid}/isPremium field is updated.
  • Boosting capacity by watching an ad: When a rewarded ad completes, the Cloud Function boosts group capacity by +5 (repeatable within 24 hours).

8. Data Retention Period and Your Right to Deletion

  • Device data: Deleted when you uninstall the app.
  • Counting history: Can be deleted manually from within the app.
  • Group data: When you leave a group, the membership record is marked as "removed" and your tasks are released. If the group admin deletes the group, all member/task/progress data is deleted from Firestore.
  • Anonymous UID deletion: You can send a request to zelvoai@gmail.com with your UID or invite code; deletion will occur within 30 days.
  • Analytics data: Firebase Analytics is auto-deleted after 14 months. Crashlytics crash data is retained for 90 days.
  • Global statistics: Stored indefinitely as they are not personally identifiable (aggregate only).

9. Children's Privacy

The app is not intended for children under 13. It does not require account creation or collect personal data, so it is not in a risky category under COPPA / GDPR-K. If you believe a child has sent data, please notify us by email; we will delete it.

10. Data Security

  • Firebase communications are TLS 1.2+ encrypted.
  • Firestore Security Rules enforce that each member can only read groups they belong to.
  • Cloud Functions verify critical operations server-side; direct writes to Firestore are largely restricted.
  • App Check prevents fake clients.
  • Premium capacity boost and rewarded ad operations are protected with rate limiting + cooldown.
